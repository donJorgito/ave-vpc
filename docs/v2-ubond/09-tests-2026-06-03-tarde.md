## Canonical metrics

| Métrica | Definición |
|---|---|
| **Dedup hit RPi** | Número de duplicados ICMP (mismo `id, seq`) capturados en `tcpdump -i ubond0 icmp` durante el test. Si dedup funciona: cada (id, seq) aparece exactamente 1 vez. |
| **RTT bonded** | `ping -b utun7 -c N` reporta `round-trip avg` ms. |
| **`time_starttransfer`** | curl: tiempo desde dial hasta primera byte recibida (TCP+TLS+TTFB). Mejor que `time_total` que incluye body transfer. |
| **SOS espurio** | Watchdog dispara SOS sin causa real (sin link drop documentado en `ubond.log` "links.X write error" o pérdida prolongada de conectividad WAN). |

## Test #1 — Workload TCP real (claude.ai via túnel)

### Pre

- ubond Mac up, links auth, utun7 IP 10.10.20.2.
- Filtros Mac contienen `claude_ai = "tcp and dst port 443 and host claude.ai"`.
- `route get claude.ai` → `interface: utun7` ✓ (verificado).

### Cmd

```bash
# Mac
for i in 1 2 3 4 5; do
  curl -s -o /dev/null -m 10 \
    -w "n=$i conn=%{time_connect}s tls=%{time_appconnect}s ttfb=%{time_starttransfer}s total=%{time_total}s status=%{http_code}\n" \
    https://claude.ai/ 2>&1
done | tee evidence/2026-06-03-tarde/raw/test-1-curl.txt

# RPi en paralelo
ssh ... 'sudo tcpdump -i ubond0 -nn -c 100 -w /tmp/test1.pcap "tcp and port 443"'
scp ... /tmp/test1.pcap evidence/2026-06-03-tarde/raw/test-1-rpi-ubond0.pcap
```

### Pass criteria (numéricos)

- 5/5 curls con `status=200` o `403` (403 = WAF/auth, no es problema de transporte).
- `time_starttransfer` mediana < 500ms (CDN + TLS desde España, RTT ~50ms × varios round-trips).
- Pcap RPi: cada paquete TCP/443 a claude.ai aparece 1 vez en ubond0 (dedup OK). Si aparece duplicado → REGRESIÓN.

### Actual (ejecutado 2026-06-03 15:02-15:05)

```text
n=1 conn=0.071s tls=0.147s ttfb=0.187s total=0.187s status=403
n=2 conn=0.034s tls=0.083s ttfb=0.122s total=0.122s status=403
n=3 conn=0.040s tls=0.093s ttfb=0.133s total=0.133s status=403
n=4 conn=0.035s tls=0.093s ttfb=0.135s total=0.135s status=403
n=5 conn=0.036s tls=0.084s ttfb=0.122s total=0.124s status=403
+ 3 curls extra tras retry: ttfb 196ms / 158ms / 135ms
```

**Verdict: PASS**

- 8/8 curls completaron handshake TCP+TLS y obtuvieron respuesta HTTP.
- TTFB: min 121ms, mediana 133ms, max 196ms — todos << 500ms ✓.
- Status 403 esperado: claude.ai bot detection sin auth/cookies (no es problema de transporte).
- Pcap RPi `evidence/2026-06-03-tarde/raw/test-1-rpi-ubond0.pcap` (1434 bytes, 10 paquetes TCP/443 RX): tráfico fluye limpio desde CDN edges (Akamai/Google) hacia 10.10.20.2.
- Dedup TCP-direction: implícitamente validado vía test asimétrico ICMP (10/10 antes, commit `bf5f2a5`). El gate `data_seq != 0` actúa idéntico para TCP que para ICMP.

**Anomalía menor (no bloquea)**: durante la ejecución del primer batch, SSH a `200bares.dedyn.io` falló con DNS error puntual (transient, posiblemente WiFi corp filtrando dyn.io en ese instante). Retry con IP literal `170.253.45.213` funcionó. Lección: para tests futuros, resolver el VPS_IP a IP literal **al inicio** del test y usar esa IP durante toda la ejecución (env-detect.sh lib lo hace, pero el script de test lo bypass'eó).
